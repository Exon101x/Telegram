# Security Policy

## The short version

A session string generated by this tool is **equivalent to the account's
password** — anyone holding it can read messages, send messages, and act
as that account, until the session is revoked from **Telegram Settings →
Devices**.

## Reporting a vulnerability

If you find a security issue in this code (not in Telegram itself, and
not "the bot operator can see my login" — that's the documented, inherent
trust model, not a bug), please report it privately rather than opening a
public issue. Include:

- A description of the issue and its impact
- Steps to reproduce
- Any relevant logs (with phone numbers, codes, and session strings
  redacted)

We'll acknowledge reports within a few days and aim to patch confirmed
issues promptly.

## Scope

**In scope:**
- Code that logs, stores, or transmits session strings, phone numbers,
  codes, or passwords beyond what's needed to complete the requested login
- Ways to bypass the `ALLOWED_USER_IDS` allowlist in the bot
- Dependency vulnerabilities in this project's own code paths

**Out of scope:**
- The inherent fact that whoever runs `telegram_session_bot.py` sees each
  user's login flow live — that's documented, not a vulnerability. See
  the README's security section before deploying it for anyone but
  yourself.
- Vulnerabilities in Telegram's own servers/apps, Pyrogram, or Telethon —
  please report those upstream.
